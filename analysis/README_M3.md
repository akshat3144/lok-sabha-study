# M3 - human coding and validation

Run everything from `lok_sabha/` with `python -I -X utf8 ...`. Tests: `python -I -X utf8 -m pytest analysis/tests pipeline/tests -q`.

## Workflow

| Step | Command | Output |
|---|---|---|
| 1. Draw samples | `analysis/sample.py` (`--force` re-draws, `--main-only` keeps `pilot_sample.csv` untouched and draws main only, `--reweight` refreshes weights only; `--main-n 400 --double-n 100` are the defaults) | `data/coding/pilot_sample.csv`, `main_sample.csv`, `sample_meta.json` |
| 2. Make sheets | `analysis/coding_sheet.py make --stage main` (each coder's sheet holds only that coder's assigned questions; re-run after a codebook change to refresh the Instructions text and version without changing the sample) | `data/coding/sheet_<coder>_<stage>.xlsx` |
| 3. Coders fill the yellow columns | Excel | |
| 4. Import | `analysis/coding_sheet.py import --stage pilot` (`--allow-incomplete` keeps only valid rows) | `data/coding/human_labels.csv` |
| 5. Disagreements (double-coded parts only) | `analysis/validate.py adjudication --stage main` | `data/coding/adjudication.csv`; fill `adjudicated_label/_evasion_type/_request_type`; re-running keeps what you typed |
| 6. Gold | `analysis/validate.py gold --stage main` | `data/coding/gold_labels.csv` (column `gold_source` = agreed / adjudicated / single) |
| 7. Report | `analysis/validate.py report --stage main --threshold 0.6 --cost modelA=1.2 --cost modelB=6.5` | `results/validation_report.md` |

Do the pilot first, refine the codebook (v1.1), then regenerate the main sheets with the frozen codebook.

## Sampling design

- Unit: question (coders code every part). Universe: question and answer present, 1-6 parts, not flagged `qa_mismatch` or `answer_garbled` (count in `sample_meta.json`). Questions with more than 6 parts are dropped (3.5% of answered questions, 6.4% of their parts; stored in `sample_meta.json`). Questions without a valid M1 score are NOT dropped (own stratum, below).
- Pilot: 50 questions, strata Lok Sabha x boilerplate flag (done and coded; never redrawn: use `sample.py --main-only --force` to redraw main only). Main (final design): 400 estimate questions plus a 20-question sanity stratum of no-answer questions (`in_estimate = False`, never used in estimates). The pilot and main are disjoint.
- Main strata: Lok Sabha (13-18) x qtype x ministry group (security/other) x risk. Risk = boilerplate-flagged answer (fixed at 25% of the sample = 100) or, for the other 300, the M1 quintile of the question-level score.
- M1 strata: the question-level score is `m1_part_mean` (mean cosine over the question's valid parts, `data/measures/m1_question.parquet`; fallback when that file is absent: mean of valid part scores in `m1_scores.parquet`; the source is recorded as `m1_score_source` in `sample_meta.json`). `m1_part_mean` is used rather than `m1_q_cos` because the coding unit is the part and the part-level scores are what M1 is validated on. Quintiles are computed within LS x qtype x ministry group among non-boilerplate questions of the main universe (pilot excluded); cells with fewer than 50 questions form one bin. When a cell's allocation k is smaller than 5, adjacent quintiles are merged into k bins (stratum label `|q12`, `|q345`, ...) so that every bin is sampled and the weights stay exact. Questions with no valid M1 score (20 of 378,846 in the universe) form their own stratum per budget group (`m1_missing|ls17`, `m1_missing|ls18`, `m1_missing|ls13,14,15,16`; one draw each). The `m1_quintile` column is the question's own quintile (0 = boilerplate, missing M1 or small cell). Note: M1 was fine-tuned on a `train`/`val` part of the corpus (`split` column in `m1_scores.parquet`); the sampling strata use the score only as a design variable, but M1 validation against gold should use the `heldout` rows.
- LS oversampling (`--ls-share "17,18:0.45"`, the default; recorded in `sample_meta.json`): the 17th and 18th Lok Sabha get 45% of the 400 estimate questions combined (90 each, so the H2/H4 17th-vs-18th contrast with PPI++ has enough gold labels); the other 220 go to LS 13-16 by the usual sqrt(N) rule. The 25% boilerplate oversample is applied within each budget group (100 in total). Weights stay exact inverse inclusion probabilities, so corpus-level estimates remain unbiased (weights sum to the eligible universe minus the pilot, and per Lok Sabha to that LS's eligible count minus its pilot questions). `--ls-share none` restores the single-pool design; the pilot is unaffected.
- Allocation within each risk group is proportional to sqrt(N_h) with a floor of 2 per cell, so starred and security cells are not starved.
- `weight` = N_stratum / n_stratum (inverse inclusion probability, conditional on the pilot). Weights of the estimate rows sum to the eligible universe minus the pilot. For part-level means give each part its question's weight and use `sum(w_q * sum_parts y) / sum(w_q * n_parts)`. Single- and double-coded questions share the same weights (the double-coding subset is a coding assignment, not a sampling stage).
- Seed 20261017 (separate sub-streams for pilot, main, sanity, coder assignment). The draw is reproducible only for the same corpus snapshot (hash in `sample_meta.json`). `sample.py` refuses to overwrite existing samples without `--force`, so a re-run cannot silently change what coders have seen.
- Ministry group: `ministry_group` column when `questions_analysis.parquet` has it (8 groups, collapsed to `security` vs `other` for stratification); otherwise HOME AFFAIRS, DEFENCE and EXTERNAL AFFAIRS = security.
- Coder assignment (main, `main_sample.csv` columns `coders` and `double_coded`): 100 of the 400 estimate questions are double-coded (`coders = "coder1;coder2"`, `double_coded = True`), a stratified random subsample of the 400 (strata: LS group {17,18} vs {13-16} x boilerplate flag, proportional allocation). The other 300 are single-coded, 150 to coder1 and 150 to coder2 (`coders = "coder1"` or `"coder2"`), balanced within the same strata and randomised with the recorded seed. The 20 sanity questions are coded by both (`double_coded = True`, `in_estimate = False`). Each coder therefore codes 100 + 150 + 20 = 270 questions, in an independent random order. Pilot: both coders code all questions.

## Coding sheet

Sheets: Instructions (codebook text, rules, examples placeholder), Coding, Meta (hidden; version hash used by the importer). Coders see Lok Sabha and ministry only; no date, session, qtype, asker, party, bloc, boilerplate flag or model output. `part_id` and the reading columns are locked (sheet protection, no password); drop-downs for label, evasion_type, request_type; an annexure column next to the answer (annexure text cut at `codebook.ANNEXURE_CHARS`, same as M2); a `check` column flags inconsistent entries. Importer rules: FULL requires evasion_type NONE_APPLICABLE (blank is auto-filled); PARTIAL/NONE require a real evasion_type; label and request_type are required; the part_id set must match the issued sheet. Each coder's main sheet holds only that coder's assigned questions; the importer checks the sheet against its own Meta `sheet_version` (stage + hash of the coder's part_id set; the codebook version embedded in the string is ignored, so sheets issued under an older codebook version, such as the coded pilot sheets, still import) and, when `<stage>_sample.csv` is next to the output file, against that coder's assigned questions. Re-running `make --stage main` after a codebook change rebuilds the sheets (new Instructions text, new version string) from the unchanged sample.

## Validation

- Reliability (label, evasion_type, request_type) uses ONLY parts coded by both coders. Primary: the double-coded estimate questions (100 questions); the 20 sanity questions are reported separately (agreement only). Statistics: Krippendorff alpha (nominal and, for label, ordinal; own implementation, checked against Krippendorff 2011's worked example: 0.743 / 0.815 / 0.849), Cohen's kappa (plain and linear-weighted), percent agreement, confusion matrix, cluster-bootstrap CIs (cluster = question); label breakdown by Lok Sabha and ministry group; evasion_type also reported on parts both coders judged non-FULL.
- Gold labels (`gold_labels.csv`, column `gold_source`): `agreed` = double-coded and the coders agree; `adjudicated` = double-coded and they disagreed on label, request_type or evasion_type, value taken from `adjudication.csv` (parts still open have an empty label and are excluded from evaluation and counted); `single` = the one coder's label for single-coded parts. If a part of a question assigned to both coders has only one coder's label imported so far it is counted as pending, not as single.
- M2 vs gold (per `model_id`): accuracy, macro-F1, kappa, CIs, design-weighted accuracy/kappa (weights from `main_sample.csv`), confusion matrix, evasion_type accuracy on gold non-FULL parts. Model rule (the report also states whether the lower 95% CI bound clears the threshold): among models with kappa >= `--threshold` (default 0.6), take the highest kappa per unit cost; costs come from `--cost id=value` (any consistent unit, e.g. projected full-corpus USD).
- M1 vs gold: AUC FULL vs NONE (and FULL vs rest), Spearman with LABEL_SCORE, Youden-optimal threshold, bootstrap CIs.
- The sanity stratum is reported separately (expect about 100% gold NONE) and excluded from M1/M2 evaluation unless `--include-sanity`.
- Note: `data/coding/gold_labels.csv` for the pilot was written by the earlier code (column `label_source`, values agree/adjudicated); re-running `validate.py gold --stage pilot` rewrites it with `gold_source`.
